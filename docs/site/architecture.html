CLM on Nemotron · encoder-agnostic branch

How a typed question becomes a probability

CLM answers a question about a state by scoring each candidate answer against that state with two small trained networks that sit on top of a frozen NVIDIA Nemotron embedding model. Nothing generates text; every answer is a softmax over cosine similarities.

The request path

One HTTP call carries a state and any number of questions. clm-serve turns each question into one state text and a list of candidate texts, fetches or computes their vectors, and returns one distribution per question.

What actually gets embedded

The question's wording ends up on the state side, appended after the context. Each option's description is embedded on its own as an action. Nemotron is an asymmetric retriever, so the two sides get different prompts: query: for states and passage: for candidates. clm-serve adds them; callers never should.

# a choice question, as the encoder sees it
query: thread:
  - role: customer
    text: I ordered the wireless headphones, but got a Bluetooth speaker instead.
  ...

What is this customer conversation primarily about?

passage: A charge, invoice, subscription or payment problem.          → billing
passage: Shipping, fulfilment or delivery of a physical item.        → delivery
passage: The customer is explicitly asking for money back.          → refund

Training and serving share one input path

A head only works on vectors built exactly the way it was trained on. So train/finetune.py and clm-serve go through the same code: schema.build_pairs lays out the texts, and EncoderSpec.prepare adds the prompt and truncates. Every checkpoint is stamped with the encoder it was trained on, and that stamp is checked when it loads.

Encoders

Both profiles are NVIDIA retrieval embedders on the Ministral-3 architecture, under the OpenMDW-1.1 licence. Heads trained on one size never transfer to the other.

Compatibility rules

  • HeadsA checkpoint records cfg["encoder"]. clm-serve --encoder X refuses any head trained on another encoder, and any head that records none (upstream releases).
  • EmbeddingsEmbedding directories and datasets carry the same stamp. finetune.py and bon_eval.py refuse to mix them across encoders.
  • WidthThe embedder rejects vectors whose width doesn't match the profile, which catches a server running the wrong model.
  • PromptsOnly clm-serve and the trainer add query: / passage: . The encoder server must not add its own.
  • TruncationThe token budget includes the prompt. States keep their end and candidates their start, so the prompt is never cut.
